# 测试指南

本文档说明如何使用批量测试工具测试电梯调度算法。

## 测试工具概览

本项目提供了三个测试相关的脚本：

1. **`generate_test_data.py`** - 生成测试数据
2. **`run_tests.py`** - 交互式批量测试（推荐）
3. **`batch_test.py`** - 测试报告生成器

---

## 快速开始

### 步骤1: 生成测试数据

如果还没有测试数据，首先运行：

```bash
uv run python tests/generate_test_data.py
```

这会在 `data/` 目录下生成10个测试场景文件。

### 步骤2: 启动模拟器

在一个终端窗口中启动模拟器服务：

```bash
uv run python -m elevator_saga.server.simulator
```

模拟器将在 `http://127.0.0.1:8000` 上运行。

### 步骤3: 运行批量测试

在另一个终端窗口中运行测试脚本：

```bash
uv run python tests/run_tests.py
```

---

## 使用 `run_tests.py` (推荐方式)

这是最简单的测试方式，提供交互式界面。

### 工作流程

1. **启动脚本**
   ```bash
   uv run python tests/run_tests.py
   ```

2. **按照提示操作**
   - 脚本会列出每个测试场景
   - 显示场景配置信息（楼层、电梯、乘客数等）
   - 等待你输入测试结果

3. **对每个场景**:

   a. 查看场景信息
   ```
   ================================================================================
   测试 [1/10]: small_morning_rush.json
   ================================================================================
   描述: 小型建筑上班高峰 - 6层楼，2部电梯
   配置: 6层 | 2部电梯 | 容量8人
   流量: 160位乘客 | 200 ticks
   难度: ★★★☆☆
   ```

   b. 在模拟器中加载对应的流量文件（如果需要）

   c. 运行控制器（在另一终端）:
   ```bash
   uv run python elevator_controller.py
   ```

   d. 等待测试完成，查看输出的性能指标:
   ```python
   {'average_system_time': 122.47297297297297,
    'average_wait_time': 122.47297297297297,
    'completed_passengers': 74,
    'p95_system_time': 194.0,
    'p95_wait_time': 194.0,
    'total_passengers': 74}
   ```

   e. 将输出复制粘贴到测试脚本的提示符处

   f. 或者输入 `skip` 跳过当前场景

4. **查看报告**

   测试完成后，脚本会自动生成：
   - `test_results/results_TIMESTAMP.json` - JSON格式的原始数据
   - `test_results/report_TIMESTAMP.md` - Markdown格式的详细报告

### 示例输出

```
================================================================================
测试完成!
================================================================================
✅ 完成测试: 8/10
📊 JSON结果: test_results/results_20251003_190530.json
📝 详细报告: test_results/report_20251003_190530.md
================================================================================
```

## 测试场景说明

### 场景类型

1. **morning_rush** - 上班高峰
   - 大量乘客从1楼到上层
   - 测试单向高密度流量

2. **evening_rush** - 下班高峰
   - 大量乘客从上层到1楼
   - 测试反向高密度流量

3. **inter_floor** - 楼层间流量
   - 随机分布的楼层间移动
   - 测试常规调度效率

4. **lunch_rush** - 午餐高峰
   - 双向流量（先下后上）
   - 测试方向转换处理

5. **burst_traffic** - 突发流量
   - 短时间大量乘客
   - 测试突发负载应对

6. **mixed** - 混合场景
   - 组合多种流量模式
   - 最真实、最具挑战

7. **asymmetric** - 非对称流量
   - 流量分布不均
   - 测试特殊场景优化

### 难度评级

- ★☆☆☆☆ - 非常简单（小建筑，低密度）
- ★★☆☆☆ - 简单（小建筑，中密度）
- ★★★☆☆ - 中等（中建筑或高峰流量）
- ★★★★☆ - 困难（大建筑或复杂流量）
- ★★★★★ - 非常困难（超大建筑或极限场景）

## 性能指标说明

### 等待时间 (Wait Time)
- 从乘客发出呼叫到登上电梯的时间
- **关键指标**，直接影响用户体验

### 系统时间 (System Time)
- 从乘客发出呼叫到到达目的地的总时间
- 包括等待时间和乘梯时间

### P95 指标
- 95%的乘客的时间上限
- 衡量极端情况下的性能
- 避免少数乘客等待过久

### 完成率 (Completion Rate)
- 在规定时间内完成服务的乘客比例
- 应该始终为 100%

---

## 性能基准参考

基于算法类型的预期性能：

| 场景规模 | 优秀 | 良好 | 可接受 | 需改进 |
|---------|------|------|--------|--------|
| 小型（6层） | <80 | 80-120 | 120-180 | >180 |
| 中型（10层） | <100 | 100-150 | 150-220 | >220 |
| 大型（15-20层） | <140 | 140-200 | 200-280 | >280 |
| 超大（25层+） | <180 | 180-250 | 250-350 | >350 |

*单位: ticks (平均等待时间)*

## 高级用法

### 自定义测试场景

编辑 `tests/generate_test_data.py` 添加新场景：

```python
# 添加自定义场景
scenarios.append({
    "filename": "custom_scenario.json",
    "data": create_test_scenario(
        name="Custom Test",
        description="自定义测试场景",
        floors=12,
        elevators=3,
        elevator_capacity=10,
        duration=300,
        scenario_type="custom",
        scale="medium",
        passengers=generate_inter_floor(12, 300)
    )
})
```

### 批量运行特定场景

修改 `tests/run_tests.py` 中的场景过滤：

```python
# 只测试小型场景
scenarios = [f for f in data_dir.glob("small_*.json")]

# 只测试高峰场景
scenarios = [f for f in data_dir.glob("*_rush.json")]
```

### 自动化测试集成

如果你想完全自动化测试流程，需要：

1. 修改模拟器以支持通过API加载流量文件
2. 修改控制器以支持批量运行模式
3. 实现自动结果收集

参考 `automated_test_template.py` 的框架。

## 故障排除

### 问题：模拟器连接失败

**解决方案**:
```bash
# 检查模拟器是否运行
lsof -i :8000

# 如果没有，启动模拟器
uv run python -m elevator_saga.server.simulator
```

### 问题：测试结果无法解析

**解决方案**:
确保复制完整的字典输出，包括花括号 `{}`。

示例正确格式:
```python
{'average_wait_time': 122.47, 'p95_wait_time': 194.0, ...}
```

### 问题：某些场景无法加载

**解决方案**:
检查 `data/` 目录中的JSON文件格式是否正确：
```bash
# 验证JSON格式
uv run python -m json.tool data/scenario.json
```

## 最佳实践

1. **按顺序测试**
   - 从简单到复杂
   - 先测试小型场景，再测试大型场景

2. **记录完整数据**
   - 不要跳过太多场景
   - 完整的数据集有助于分析

3. **多次测试**
   - 对关键场景进行多次测试
   - 取平均值以获得更可靠的结果

4. **保存历史记录**
   - 保留所有测试报告
   - 跟踪算法改进的历史

5. **分析报告**
   - 仔细阅读生成的Markdown报告
   - 识别算法的优势和劣势
   - 针对性地优化算法
