## 1. 概述

本电梯调度算法是一个基于 **SCAN（电梯算法）** 和 **智能评分系统** 的混合调度策略，旨在最小化乘客的平均等待时间和P95等待时间。算法通过动态追踪乘客请求、电梯状态和负载情况，实现高效的多电梯协同调度。

### 1.1 算法名称

**OptimizedElevatorController** - 优化电梯控制器

### 1.2 适用场景

- 中小型建筑（6-20层）
- 多电梯系统（2-8部电梯）
- 混合流量模式（楼层间流量、上下班高峰等）

---

## 2. 算法设计目标

### 2.1 主要目标

1. **最小化平均等待时间**：减少所有乘客从呼叫到上电梯的平均时间
2. **最小化P95等待时间**：确保95%的乘客等待时间在可接受范围内
3. **负载均衡**：合理分配任务到各部电梯，避免某部电梯过载

### 2.2 次要目标

- 减少电梯空驶距离
- 提高电梯利用率
- 降低能耗（减少频繁换向）

---

## 3. 核心算法策略

### 3.1 SCAN算法（电梯算法）

SCAN算法是磁盘调度算法的经典方案，在电梯调度中同样适用：

**原理**：
- 电梯在一个方向上持续移动
- 服务该方向上的所有请求
- 到达末端后反向，重复上述过程

**优势**：
- 避免频繁换向，减少机械损耗
- 提供可预测的服务时间
- 防止饥饿问题（所有请求最终都会被服务）

**实现细节**：
```python
# 在 on_elevator_approaching() 中实现
if direction == "up" and self.waiting_up[floor_num]:
    should_stop = True
elif direction == "down" and self.waiting_down[floor_num]:
    should_stop = True
```

### 3.2 智能电梯分配

当新的乘客请求到来时，系统通过评分机制选择最优电梯：

**评分因素**：
1. **距离** - 电梯当前位置到请求楼层的距离
2. **负载** - 电梯当前载客量
3. **方向匹配度** - 电梯移动方向与请求方向的匹配程度

**评分公式**：
```
score = distance + (load_factor × 10)

# 方向匹配奖励
if 电梯方向与请求方向一致 且 电梯会经过请求楼层:
    score = score × 0.5

# 方向冲突惩罚
if 电梯方向与请求方向相反 且 需要先完成当前方向所有请求:
    score = score + 20
```

### 3.3 最近邻策略

对于空闲电梯，采用最近邻策略：
- 扫描所有楼层，找到有等待乘客的楼层
- 计算距离，选择最近的楼层
- 立即前往该楼层

## 4. 数据结构设计

### 4.1 等待队列

```python
# 按方向分类的等待乘客集合
waiting_up: Dict[int, Set[int]]    # 楼层号 -> 上行乘客ID集合
waiting_down: Dict[int, Set[int]]  # 楼层号 -> 下行乘客ID集合
```

**设计考虑**：
- 使用 `Set` 避免重复
- 按楼层索引，O(1) 查询
- 按方向分类，便于SCAN算法实现

### 4.2 电梯目标追踪

```python
# 电梯的目标楼层列表
elevator_targets: Dict[int, List[int]]  # 电梯ID -> 目标楼层列表
```

**作用**：
- 追踪每部电梯的待访问楼层
- 辅助决策是否分配新任务
- 用于负载评估

## 5. 事件处理流程

### 5.1 初始化流程（on_init）

```
1. 记录楼层数和电梯数
2. 初始化所有楼层的等待队列（上行/下行）
3. 初始化所有电梯的目标列表
```

### 5.2 乘客呼叫流程（on_passenger_call）

```
输入: 乘客对象, 楼层对象, 方向
│
├─→ 1. 将乘客ID添加到对应楼层的等待队列
│      - 上行添加到 waiting_up[floor]
│      - 下行添加到 waiting_down[floor]
│
└─→ 2. 调用电梯分配算法
       └─→ _assign_elevator_to_call(floor, direction)
           │
           ├─→ 2.1 找到最佳电梯（_find_best_elevator）
           │      └─→ 遍历所有电梯，计算评分，选择最低分
           │
           └─→ 2.2 指令电梯前往该楼层
                  └─→ elevator.goto_floor(floor)
```

### 5.3 电梯接近楼层流程（on_elevator_approaching）

```
输入: 电梯对象, 楼层对象, 方向
│
├─→ 1. 检查是否有乘客需要下车
│      └─→ 遍历电梯内乘客，检查 destination_floor
│
├─→ 2. 检查是否有同向等待乘客
│      ├─→ 上行 && waiting_up[floor] 不为空
│      └─→ 下行 && waiting_down[floor] 不为空
│
├─→ 3. 特殊情况：楼层边界处理
│      ├─→ 顶层：检查下行等待
│      └─→ 底层：检查上行等待
│
└─→ 4. 决策：需要停靠则调用 elevator.stop()
```

### 5.4 电梯停靠流程（on_elevator_stopped）

```
输入: 电梯对象, 楼层对象
│
├─→ 1. 从电梯目标列表中移除当前楼层
│      └─→ elevator_targets[elevator.id].remove(floor_num)
│
└─→ 2. 等待乘客上下车
       └─→ 由框架自动触发 on_passenger_board 和 on_passenger_alight
```

### 5.5 乘客上车流程（on_passenger_board）

```
输入: 电梯对象, 乘客对象
│
├─→ 1. 从等待队列中移除乘客
│      ├─→ waiting_up[origin_floor].remove(passenger_id)
│      └─→ waiting_down[origin_floor].remove(passenger_id)
│
└─→ 2. 注册目的地楼层
       └─→ elevator.goto_floor(destination)
           └─→ 添加到 elevator_targets[elevator.id]
```

### 5.6 电梯空闲流程（on_elevator_idle）

```
输入: 电梯对象
│
├─→ 1. 查找最近的等待请求
│      └─→ _find_nearest_waiting_call(current_floor)
│         └─→ 遍历所有楼层，找到最近有等待乘客的楼层
│
└─→ 2. 如果找到，指令电梯前往
       └─→ elevator.goto_floor(best_floor)
```

## 6. 电梯分配算法

### 6.1 评分系统详解

评分系统是算法的核心，决定了哪部电梯响应哪个请求。

#### 6.1.1 基础评分

```python
distance = abs(elevator.current_floor - target_floor)
score = distance
```

**含义**：距离越近，评分越低，优先级越高。

#### 6.1.2 负载惩罚

```python
load_factor = len(elevator.passengers) / elevator.capacity
score += load_factor * 10
```

**含义**：
- 空电梯：load_factor = 0，无惩罚
- 半满电梯：load_factor = 0.5，惩罚 +5
- 满载电梯：load_factor = 1.0，惩罚 +10

**目的**：负载均衡，避免某部电梯过载。

#### 6.1.3 方向匹配奖励

```python
if elevator.direction == direction:
    if direction == "up" and elevator.current_floor <= target_floor:
        score *= 0.5  # 强奖励
    elif direction == "down" and elevator.current_floor >= target_floor:
        score *= 0.5  # 强奖励
```

**含义**：
- 电梯正朝着请求方向移动
- 且会经过请求楼层
- 评分减半，大幅提高优先级

**效果**：
- 减少乘客等待时间
- 符合SCAN算法逻辑
- 提高电梯利用率

#### 6.1.4 方向冲突惩罚

```python
if elevator.direction == "up" and direction == "down" and elevator.current_floor < target_floor:
    score += 20
elif elevator.direction == "down" and direction == "up" and elevator.current_floor > target_floor:
    score += 20
```

**含义**：
- 电梯正在相反方向移动
- 需要先完成当前方向的所有任务
- 再返回处理此请求

**效果**：
- 降低优先级
- 避免频繁换向
- 维护SCAN算法的连续性

### 6.2 评分示例

假设场景：
- 请求：5楼，上行
- 电梯A：3楼，上行，载客2/8
- 电梯B：7楼，下行，载客5/8
- 电梯C：5楼，停止，载客0/8

**电梯A评分**：
```
distance = |3 - 5| = 2
load_factor = 2/8 = 0.25
score = 2 + 0.25×10 = 4.5
方向匹配: 上行 && 3 <= 5 → score = 4.5 × 0.5 = 2.25 ✓ 最佳
```

**电梯B评分**：
```
distance = |7 - 5| = 2
load_factor = 5/8 = 0.625
score = 2 + 0.625×10 = 8.25
方向冲突: 下行 && 7 > 5 → score = 8.25 + 20 = 28.25
```

**电梯C评分**：
```
distance = |5 - 5| = 0
load_factor = 0/8 = 0
score = 0 + 0×10 = 0
无方向匹配/冲突 → score = 0
```

**结果**：
- 电梯C距离最近，但处于停止状态
- 电梯A评分2.25，因为方向匹配获得奖励
- 实际上，电梯C评分最低（0），会被选中

**修正**：在实际实现中，已停靠在目标楼层的电梯评分为0，优先级最高，这是合理的。

## 7. 优化策略

### 7.1 避免饥饿

**问题**：某些请求可能长时间得不到服务。

**解决方案**：
- SCAN算法保证所有楼层最终会被访问
- 最近邻策略确保空闲电梯主动寻找等待乘客
- 评分系统考虑距离，远处请求最终会因为其他电梯靠近而被服务

### 7.2 边界处理

**问题**：顶层和底层的特殊性。

**解决方案**：
```python
# 在 on_elevator_approaching 中
if floor_num == self.num_floors - 1 and self.waiting_down[floor_num]:
    should_stop = True  # 顶层检查下行
elif floor_num == 0 and self.waiting_up[floor_num]:
    should_stop = True  # 底层检查上行
```

### 7.3 减少空驶

**策略**：
- 空闲电梯前往最近的等待请求（最近邻）
- 非空闲电梯优先服务同向请求（SCAN）
- 评分系统惩罚方向冲突，减少来回

### 7.4 负载均衡

**策略**：
- 评分系统中的负载惩罚因子
- 负载高的电梯评分增加，降低优先级
- 新请求倾向于分配给负载低的电梯

## 8. 算法复杂度分析

### 8.1 时间复杂度

| 操作 | 复杂度 | 说明 |
|------|--------|------|
| 乘客呼叫 | O(E) | E为电梯数，需遍历所有电梯评分 |
| 电梯接近 | O(P) | P为电梯内乘客数，检查是否有人下车 |
| 电梯停靠 | O(1) | 仅移除目标楼层 |
| 乘客上车 | O(1) | Set操作，O(1)删除 |
| 电梯空闲 | O(F) | F为楼层数，查找最近等待请求 |

### 8.2 空间复杂度

| 数据结构 | 复杂度 | 说明 |
|----------|--------|------|
| waiting_up/down | O(F×N) | F楼层数，N乘客数 |
| elevator_targets | O(E×F) | E电梯数，最坏情况每部电梯访问所有楼层 |

**总体空间复杂度**：O(F×N + E×F)

在实际应用中：
- F ≈ 10-20（楼层数）
- E ≈ 2-8（电梯数）
- N ≈ 数十到数百（乘客数）

空间开销可接受。

## 9. 算法优缺点

### 9.1 优点

1. **高效性**
   - SCAN算法减少换向次数
   - 评分系统快速找到最优电梯
   - 时间复杂度低，实时性好

2. **公平性**
   - 避免饥饿问题
   - 所有请求都会被服务
   - 边界处理保证端点楼层服务质量

3. **负载均衡**
   - 评分系统考虑电梯负载
   - 避免单部电梯过载
   - 提高整体系统吞吐量

4. **可扩展性**
   - 适用于不同规模建筑
   - 支持多部电梯协同
   - 参数可调（评分权重）

### 9.2 缺点

1. **局部最优**
   - 评分系统基于当前状态
   - 未考虑未来请求趋势
   - 可能错过全局最优解

2. **缺乏预测**
   - 不学习历史流量模式
   - 无法预测上下班高峰
   - 不做前瞻性部署

3. **参数固定**
   - 评分权重硬编码
   - 未针对不同场景优化
   - 缺乏自适应能力

4. **极端场景**
   - 超高峰流量可能性能下降
   - 非常不均匀的流量分布可能导致某些电梯空闲
   - 电梯容量限制未充分利用

### 9.3 改进方向

1. **机器学习**
   - 学习历史流量模式
   - 预测未来请求
   - 动态调整评分权重

2. **前瞻性调度**
   - 考虑未来N步的状态
   - 使用动态规划或启发式搜索
   - 优化全局等待时间

3. **场景识别**
   - 识别上下班高峰、午休等场景
   - 针对不同场景使用不同策略
   - 自适应切换算法

4. **群体智能**
   - 电梯间协同决策
   - 区域划分策略
   - 分布式调度

---

## 10. 总结

本电梯调度算法结合了经典的SCAN算法和现代的智能评分系统，在保证公平性的前提下，通过多维度评分机制实现高效的多电梯协同调度。算法设计简洁、实现高效、可扩展性强，适用于中小型建筑的电梯调度需求。

通过合理的数据结构设计和事件驱动的处理流程，算法能够实时响应乘客请求，动态调整电梯运行策略，有效降低乘客平均等待时间和P95等待时间。

虽然算法存在局部最优和缺乏预测等局限，但在大多数实际场景中已能提供令人满意的性能表现。未来可通过引入机器学习、前瞻性调度等技术进一步优化算法性能。
